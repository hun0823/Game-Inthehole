## 2. 난이도 설계 — 변수 프레임워크

### 2.1 핵심 가설 (기획자 메모)

> **플레이트 기울임 횟수(이동 수)가 많을수록 체감 난이도 상승**

→ **맞는 방향**. 다만 **이동 수만으로는 부족** — 같은 이동 수라도 “실수 한 번에 망함” vs “여유 있음” 차이가 큼.

### 2.2 난이도 점수에 쓸 변수 (권장)

| 변수 | 설명 | 난이도 ↑ 방향 |
|------|------|----------------|
| `gridSize` | N×N | N 증가 (분기·시야 부담) |
| `optimalMoves` | 최적(또는 검증된) 최소 기울임 수 | 값 증가 |
| `playerMoves` / `optimalMoves` | 플레이어 실제 이동 / 최적 | 1에 가까울수록 빡셈 (별 3개 기준) |
| `wallDensity` | 엣지 벽 수 / 가능한 내부 엣지 수 `2·N·(N-1)` | 증가 |
| `edgeCount` | 가로·세로 벽 변의 개수 (기둥 칸 수는 폐기) | 증가 |
| `branching` | 한 상태에서 유효한 기울임 방향 수 평균 | 감소 시 막막함 ↑ |
| `deadEndRisk` | 한 번 잘못 굴리면 복구 불가 경로 비율 | 증가 |
| `specialTileRatio` | 유리·워프 등 특수 칸 비율 | 증가 (규칙 추가) |
| `visualClutter` | 벽·색 유사도 (실수 유발) | 증가 (후순위) |

### 2.3 `optimalMoves` 구하는 방법 (구현 메모)

1. **BFS/DFS** — 상태 = `(ballRow, ballCol)`, 행동 = 4방 기울임, 목표 = hole  
   - 스테이지당 최단 경로 길이 = `optimalMoves` (이동 1회 = 기울임 1회)
2. 레벨 에디터/CI에서 **자동 검증**:
   - `unsolvable` → 빌드 실패
   - `optimalMoves` > 해당 N×N 상한 → 경고
3. **별점 기준 (안)**:
   - ★3: `moves <= optimalMoves`
   - ★2: `moves <= optimalMoves + 1`
   - ★1: 클리어

### 2.4 그리드 크기별 가이드라인 (초안, 밸런스 후 조정)

| 크기 | optimalMoves (일반) | wallDensity | 비고 |
|------|---------------------|-------------|------|
| 2×2 | 1~2 | 0~0.1 | 튜토리얼 |
| 3×3 | 2~5 | 0.1~0.25 | 코너·우회 |
| 4×4 | 4~8 | 0.15~0.35 | |
| 5×5 | 6~12 | 0.2~0.4 | Phase A 상한 |
| 6×6+ | 8~18+ | 단계적 증가 | 특수 타일 병행 |

### 2.5 난이도 곡선 (월드 구성 안)

- **월드 1 (2~3):** 규칙 학습, optimal 2~4  
- **월드 2 (3~4):** 벽 밀도 ↑, optimal 4~7  
- **월드 3 (4~5):** 우회·함정, optimal 6~10  
- **월드 4 (5 only):** 종합 + 유리벽 튜토리얼  
- 이후 6×6~: 특수 타일·워프

### 2.6 레벨 데이터 스키마 (엣지 벽, `shared/levels.json` version 8)

모든 칸은 바닥이다. 벽·유리·색 게이트는 **칸과 칸 사이의 변**이다.  
`pillars`(막힌 칸을 네 변으로 펼치던 모델)는 제거했다. 그 방식은 칸 내부를 못 들어가게 하고 벽이 박스 모양이 되었다.

- `hWalls[].{row,col}` — `row`와 `row+1` 사이, 열 `col` (`row < size-1`)
- `vWalls[].{row,col}` — `col`과 `col+1` 사이, 행 `row` (`col < size-1`)
- 유리(`glassH`/`glassV`)와 색 게이트(`coloredH`/`coloredV`)는 **같은 좌표**
- 이어 붙인 변은 L / T / 직선 보석 막대가 된다. 한 칸의 네 변을 모두 막지 않는다.
- `par` = BFS 최적 기울임 수 (버튼 프레스 1회는 이동 1). 이동 한도는 HUD의 `par`, 실패는 `par+3`
- 웹이 이 파일을 읽는다. Unity `Resources/Levels`는 옛 pillar JSON이라 **out of sync**

형식 예시(실제 스테이지 덤프 아님):

```json
{
  "id": 42,
  "name": "Press first",
  "size": 6,
  "hWalls": [{ "row": 2, "col": 0 }, { "row": 2, "col": 1 }],
  "vWalls": [{ "row": 1, "col": 3 }],
  "glassH": [],
  "glassV": [],
  "coloredH": [{ "row": 3, "col": 2, "color": "red" }],
  "coloredV": [{ "row": 4, "col": 1, "color": "red" }],
  "buttons": [{ "row": 1, "col": 1, "color": "red" }],
  "ball": { "row": 0, "col": 0 },
  "hole": { "row": 5, "col": 5 },
  "par": 14
}
```

빈 유리·색·버튼 배열은 파일에서 생략해도 된다. 로더는 없으면 빈 격자로 본다.

## 3. 특수 규칙 (변수 타일)

### 3.1 유리벽 (Glass Wall) — Phase B 우선

| 항목 | 내용 |
|------|------|
| **동작** | 공이 그 엣지를 **처음 통과 시도** → 금 간 상태, **통과 불가** |
| **2번째** | 같은 엣지로 다시 밀리면 → **파괴**, 이후 일반 통로 |
| **카운트** | “기울임 1회”가 아니라 **그 벽에 공이 닿은 슬라이드 시도 횟수**로 할지, “플레이어 턴 수”로 할지 → **슬라이드 시도** 권장 (직관적) |
| **연출** | 크랙 텍스처 → 파편 VFX + 짧은 SFX |
| **난이도** | 같은 optimal 경로라도 **실질 이동 수 +1~2** 체감 |

**시뮬레이션 확장:** `GameSimulation`에 `glassWalls[edge] → hits (0|1|broken)` 상태 추가.

### 3.2 워프 (Warp) — Phase C

- 칸 A ↔ 칸 B 쌍; 공 진입 시 순간이동 후 **같은 방향으로 슬라이드 계속** (또는 정지 — 밸런스 결정 필요)
- 5×5 이후, optimal 검증 필수

### 3.3 기타 후보 (메모)

- **일회용 바닥** (한 번 지나면 함몰)
- **방향 화살표 바닥** (강제 방향)
- **이동 제한 횟수** 스테이지 (최대 N번 기울임)

## 4. 메타 진행 · 리텐션 · 리워드

### 4.1 루프 (상위권 캐주얼 표준)

```
스테이지 플레이 → 클리어 → 보상 획득 → 메타에 사용 → 다음 스테이지 / 일일 / PvP
```

### 4.2 클리어 보상 (1판 직후)

| 보상 | 용도 |
|------|------|
| **코인** (소프트) | 스킨·힌트·Undo 구매 |
| **별** (1~3) | 월드 언락·게이트 |
| **경험치** | 계정 레벨 → 기능 언락 |
| **가챠 티켓** (저빈도) | 스킨 뽑기 |

- **광고 (선택):** 보상 2배, 유리벽 스테이지 실패 후 **1회 Undo**  
- Block Blast 리뷰 교훈: **강제 긴 전면광고** 지양 → 클리어·메뉴 전환에만

### 4.3 수집 · 커스터마이즈 (아바타/테마)

| 카테고리 | 예시 | 희귀도 |
|----------|------|--------|
| **공 스킨** | 금속, 유리, 이모지, 시즌 | ★~★★★ |
| **테이블 배경** | 나무, 대리석, 우주, 시즌 | ★~★★★ |
| **벽 스킨** | 나무 / 유리 / 브릭 / 네온 | ★~★★ |
| **구멍 이펙트** | 링 색, 파티클 | ★★ |
| **트레이 장식** | 테이블 위 피규어·스티커 (배경 인형) | ★★~★★★ |

- **장착 슬롯:** 공 1 + 테이블 1 + 벽 1 + FX 1 + 장식 1  
- **획득 경로:** 스테이지 첫 클리어, 별 모음, 일일 미션, 시즌 패스, (PvP) 랭크 보상

### 4.4 일일 · 주간 (재방문)

## 5. 매치 모드 (Phase D) — 1:1 PvP

### 5.1 개요

- 보드: **4×4 또는 5×5**
- **턴제** — 블루 vs 레드
- **블루 공 → 블루 구멍**, **레드 공 → 레드 구멍** (자기 색만 클리어)
- **먼저 자기 구멍에 넣는 쪽 승리**

### 5.2 턴 구조 (안)

| 페이즈 | 행동 |
|--------|------|
| 내 턴 | (1) **기울이기** 1회 **또는** (2) **벽 설치** 1개 (엣지, 제한 규칙) |
| 상대 턴 | 동일 |
| 제한 | 턴 시간 15~30초, 연장 3회/판 |

- **벽 설치:** 남은 “벽 카운트” 소모, 상대 경로 방해 (밸런스 핵심)
- **동시 슬라이드**는 하지 않음 (턴제로 명확히)

### 5.3 랭크 · 매칭

- **ELO 또는 티어** (브론즈 ~ 챌린저)
- 시즌 4~6주, 시즌 스킨
- **친선 / 랭크** 분리
- 연승 보너스 코인 (과도한 스노우볼 방지 캡)

### 5.4 기술 메모 (나중에)

- Photon Fusion / Unity Netcode / PlayFab Turn-based 등 비교
- **결정론 시뮬** 필수: `GameSimulation`을 서버·클라 공유
- 치트 방지: 행동만 서버 검증

## 9. 행성 캠페인과 필요성 (2026-10-10)

규칙은 `js/game.js` 한 곳이다. 솔버(`tools/tilt_solver.py`)와 힌트는 그 규칙을 그대로 따라간다. 테마·상점·언어는 슬라이드를 바꾸지 않는다.

캠페인은 행성 12개 × 스테이지 12개 = 144판이다. 행성 안 보드 크기는 `3,3,4,4,5,5,5,6,6,6,7,7`. 행성 1은 항상 열려 있고, 다음 행성은 이전 행성 12판을 모두 클리어하면 열린다. 행성을 깨면 그 행성의 공+골 세트를 받는다. 상점에서 미리 살 수도 있다. 받으면 자동 장착하지 않는다. 보드 테마와 장착한 공은 별개다.

| 행성 | 트릭 | 보상 공 |
|------|------|---------|
| 나무 Wood | 벽만 | 참나무 + 옹이 구멍 |
| 사막 Desert | 모래, 모래폭풍 | 사구 |
| 얼음 Ice | 얼음 바닥 | 눈덩이 |
| 바다 Ocean | 소용돌이(순간이동), 해류(일방통행) | 비치볼 |
| 수정 Crystal | 유리 (1타 금, 2타 파쇄) | 구슬 |
| 장난감 Toy | 버튼 문 | 장난감공 |
| 버섯 Mushroom | 포자 안개 | 버섯공 |
| 사탕 Candy | 젤리 | 젤리 |
| 용암 Lava | 마그마 | 운석 |
| 정글 Jungle | 흔들리는 덩굴 | 코코넛 |
| 외계 Alien | 트릭 둘 | 외계점액 |
| 기계 Machine | 트릭 셋 이상 | 톱니 |

3×3에서는 일방통행과 움직이는 벽이 GAP을 만족하는 배치가 없다. 그래서 바다 1–2는 소용돌이만, 해류는 4×4부터다. 정글 1–2는 벽 퍼즐이고 덩굴은 4×4(그 행성의 3번째 판)부터다. 사탕 3×3은 점프가 보드 밖으로 나가 젤리 위에서 멈추는 정지를 트릭으로 쓴다. 용암 3×3은 한 기울이기 안에 건너는 다리(par 2)다. 무너지는 바닥 규칙은 엔진에 남아 있지만, 이번 용암 판에는 넣지 않았다. 타이밍 트릭이 마그마다.

코인은 메카닉에서 뺐다. 엔진의 코인 보너스 코드는 남아 있어도 새 레벨에는 코인이 없다.

### 젤리

공이 **굴러 들어가** 젤리 칸에 닿을 때만 점프한다. 기울이기 시작 때 이미 젤리 위에 있으면 점프하지 않는다. 진행 방향으로 다음 칸을 건너뛰고, 그 다음 칸(두 칸 앞)에 내려 계속 미끄러진다. 젤리와 착지 칸 사이의 가장자리(벽, 유리, 문, 일방통행, 덩굴)는 무시한다. 무시된 유리는 금 가지 않는다. 건너뛴 칸은 들어가지 않는다. 경로에는 젤리 칸 다음에 착지 칸이 비인접으로 기록된다. 착지 칸이 보드 밖이거나, 이미 터진 마그마이거나, 무너진 바닥이면 공은 **젤리 위에서 멈추고** 그 기울이기가 끝난다. 얼음 위여도 그렇다. 착지가 또 젤리면 이어서 점프한다(최대 한 변 길이×2). 성공한 착지 뒤에는 구멍이면 클리어, 모래면 정지, 얼음 규칙이 착지 칸에 적용된다. 젤리와 모래는 겹치지 않는다.

### 마그마

각 분출은 `{칸, at}`이다. 이번 기울이기 시작 시점의 소모된 기울이기 수가 `at` 이상이면 그 칸은 막혀 있어 들어갈 수 없다. `at - 1`일 때는 금이 빛날 뿐, 아직 들어갈 수 있다(예고는 시각만). 공 **위**에서 터져도 공을 묻지 않는다. 나가는 것은 되고, 다시 들어가는 것은 안 된다. 슬라이드 전체는 그 기울이기 **시작** 횟수를 쓴다. 횟수는 공이 움직인 기울이기 또는 버튼 누름 뒤에 1 오른다. 제자리 부딪힘은 오르지 않는다. BFS 상태에 기울이기 수가 들어가고, 모든 분출이 끝난 뒤의 상한에서 고정된다.

필요성에는 두 가지가 있다. **지나가기:** 해가 `at` 전에 그 칸을 밟고, `at`을 0으로 고정(처음부터 막힘)하면 par가 3 이상 늘거나 풀 수 없게 된다. 분출 배열을 통째로 지워도 par가 그대로일 수 있다. 이른 길이 남아 있기 때문이다. 판정은 “이미 닫혀 있으면 퍼즐이 깨지는가”이다. **막이:** 기울이기가 끝난 바로 앞칸이 이미 터진 마그마이고, 그 가장자리는 벽이 아니다. 분출을 지우면 par가 3 이상 바뀌거나 풀 수 없게 된다. `at` 전에 닿을 수 없는 칸은 벽과 같아서 거절한다.

### 필요성 (GAP = 3)

트릭은 장식이 아니다. 최적해가 그 장치와 만나고, 중화하면 par가 3 이상 달라지거나 풀 수 없어야 한다. 차이 0–1은 장식이다.

- 벽만인 판: 벽을 빼면 par가 2 이상 짧아진다.
- 모래: 해가 그 칸에서 기울이기를 끝내고, 진행 방향 다음 칸은 보드 안이며 벽이 없다. 모래를 빼면 par가 3 이상 늘거나 불가능. 짧은 미끄럼 중간의 모래는 기울이기 하나를 둘로 쪼갤 뿐(+1)이라 거절.
- 얼음: 해가 얼음을 지나쳐 가고(그 기울이기의 마지막 칸이 아님), 멈춘 뒤 진행 방향은 열려 있다. 얼음을 빼면 불가능하거나 par+3.
- 일방통행: 화살 방향으로 건너거나, 화살 반대에서 막혀 서는 것 모두 상호작용이다. 가장자리를 열어 버리는 경우와 벽으로 바꾸는 경우 둘 다 par가 바뀌어야 한다. 큰 쪽 변화 ≥ 3, 작은 쪽 ≥ 2. 벽과 같은 일방통행은 장식이다. 일방통행이 par를 줄이는 정지일 수도 있다.
- 순간이동: 끄면 불가능하거나 par+3. 해는 인접하지 않은 칸으로 뛰어야 한다.
- 유리: 해가 판을 부순다(상태 2). 유리 전부를 벽으로 보면 불가능하거나 par+3.
- 문: 허용 마스크 0, 그리고 각 색을 빼면 풀 수 없다. 해는 색 가장자리를 건넌다. 처음부터 모두 열려 있으면 par가 2 이상 준다.
- 포자 안개: 규칙 플래그를 지워도 경로는 같다. 필요성은, 해가 들어가는 안개 칸에 닿은 숨은 벽을 빼면 par가 2 이상 주는 것이다.
- 젤리: 같은 축으로 길이 2인 점프가 젤리에서 나가거나, 착지가 보드 밖인 정지로 젤리에서 끝난다. 젤리를 빼면 par가 3 이상 나빠지거나 불가능.
- 마그마: 위 문단.
- 무너지는 바닥: 해가 각 칸을 정확히 한 번 밟고 떠난다. 중화하면 어느 쪽으로든 par가 3 이상 바뀐다.
- 움직이는 벽: 해가 그 위상에서 열린 덩굴 가장자리를 건넌다. 덩굴을 빼면 어느 쪽으로든 par가 3 이상 바뀐다. 위상은 위치가 바뀌거나 유리를 맞았을 때만 뒤집힌다. 버튼만 누르거나 제자리 부딪힘은 뒤집지 않는다.
- 섞인 판: 들어 있는 트릭마다 자기 검사를 통과해야 한다.

같은 맵의 회전·대칭(이면군 D4)은 크기와 상관없이 거절한다. 퍼지 근사 중복(자카드 ≥ 0.85, 또는 같은 공·구멍에서 해밍 ≤ 2)은 한 변이 5 이상일 때만 적용한다.

힌트 재생의 행동 수는 저장된 par와 같고, 구멍에서 끝난다. 검증은 `tools/validate_levels.py`와 힌트 재실행이다.
