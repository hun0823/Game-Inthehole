## 1. 스테이지 규모 & 개발 단계

| 단계 | 그리드 | 목표 |
|------|--------|------|
| **Phase A (현재)** | 2×2 ~ **5×5** | 코어 완성, 30~50 스테이지, Unity 3D 폴리시 |
| Phase B | 6×6 ~ 8×8 | 특수 타일·유리벽 본격 |
| Phase C | 9×9 ~ **10×10** | 워프·고난도·일일 챌린지 |
| Phase D | 매치 모드 | 4×4 / 5×5 PvP |

- **최종 비전:** 2×2 → 10×10 난이도 곡선
- **당장:** 5×5 까지만 레벨·로직·밸런스 파이프라인 구축

## 2. 난이도 설계 — 변수 프레임워크

### 2.1 핵심 가설 (기획자 메모)

> **플레이트 기울임 횟수(이동 수)가 많을수록 체감 난이도 상승**

→ **맞는 방향**. 다만 **이동 수만으로는 부족** — 같은 이동 수라도 “실수 한 번에 망함” vs “여유 있음” 차이가 큼.

### 2.2 난이도 점수에 쓸 변수 (권장)

| 변수 | 설명 | 난이도 ↑ 방향 |
|------|------|----------------|
| `gridSize` | N×N | N 증가 (분기·시야 부담) |
| `optimalMoves` | 최적(또는 검증된) 최소 기울임 수 | 값 증가 |
| `playerMoves` / `optimalMoves` | 플레이어 실제 이동 / 최적 | 1에 가까울수록 빡셈 (별 3개 기준) |
| `wallDensity` | 엣지 벽 수 / 가능한 내부 엣지 수 `2·N·(N-1)` | 증가 |
| `edgeCount` | 가로·세로 벽 변의 개수 (기둥 칸 수는 폐기) | 증가 |
| `branching` | 한 상태에서 유효한 기울임 방향 수 평균 | 감소 시 막막함 ↑ |
| `deadEndRisk` | 한 번 잘못 굴리면 복구 불가 경로 비율 | 증가 |
| `specialTileRatio` | 유리·워프 등 특수 칸 비율 | 증가 (규칙 추가) |
| `visualClutter` | 벽·색 유사도 (실수 유발) | 증가 (후순위) |

### 2.3 `optimalMoves` 구하는 방법 (구현 메모)

1. **BFS/DFS** — 상태 = `(ballRow, ballCol)`, 행동 = 4방 기울임, 목표 = hole  
   - 스테이지당 최단 경로 길이 = `optimalMoves` (이동 1회 = 기울임 1회)
2. 레벨 에디터/CI에서 **자동 검증**:
   - `unsolvable` → 빌드 실패
   - `optimalMoves` > 해당 N×N 상한 → 경고
3. **별점 기준 (안)**:
   - ★3: `moves <= optimalMoves`
   - ★2: `moves <= optimalMoves + 1`
   - ★1: 클리어

### 2.4 그리드 크기별 가이드라인 (초안, 밸런스 후 조정)

| 크기 | optimalMoves (일반) | wallDensity | 비고 |
|------|---------------------|-------------|------|
| 2×2 | 1~2 | 0~0.1 | 튜토리얼 |
| 3×3 | 2~5 | 0.1~0.25 | 코너·우회 |
| 4×4 | 4~8 | 0.15~0.35 | |
| 5×5 | 6~12 | 0.2~0.4 | Phase A 상한 |
| 6×6+ | 8~18+ | 단계적 증가 | 특수 타일 병행 |

### 2.5 난이도 곡선 (월드 구성 안)

- **월드 1 (2~3):** 규칙 학습, optimal 2~4  
- **월드 2 (3~4):** 벽 밀도 ↑, optimal 4~7  
- **월드 3 (4~5):** 우회·함정, optimal 6~10  
- **월드 4 (5 only):** 종합 + 유리벽 튜토리얼  
- 이후 6×6~: 특수 타일·워프

### 2.6 레벨 데이터 스키마 (엣지 벽, `shared/levels.json` version 8)

모든 칸은 바닥이다. 벽·유리·색 게이트는 **칸과 칸 사이의 변**이다.  
`pillars`(막힌 칸을 네 변으로 펼치던 모델)는 제거했다. 그 방식은 칸 내부를 못 들어가게 하고 벽이 박스 모양이 되었다.

- `hWalls[].{row,col}` — `row`와 `row+1` 사이, 열 `col` (`row < size-1`)
- `vWalls[].{row,col}` — `col`과 `col+1` 사이, 행 `row` (`col < size-1`)
- 유리(`glassH`/`glassV`)와 색 게이트(`coloredH`/`coloredV`)는 **같은 좌표**
- 이어 붙인 변은 L / T / 직선 보석 막대가 된다. 한 칸의 네 변을 모두 막지 않는다.
- `par` = BFS 최적 기울임 수 (버튼 프레스 1회는 이동 1). 이동 한도는 HUD의 `par`, 실패는 `par+3`
- 웹이 이 파일을 읽는다. Unity `Resources/Levels`는 옛 pillar JSON이라 **out of sync**

형식 예시(실제 스테이지 덤프 아님):

```json
{
  "id": 42,
  "name": "Press first",
  "size": 6,
  "hWalls": [{ "row": 2, "col": 0 }, { "row": 2, "col": 1 }],
  "vWalls": [{ "row": 1, "col": 3 }],
  "glassH": [],
  "glassV": [],
  "coloredH": [{ "row": 3, "col": 2, "color": "red" }],
  "coloredV": [{ "row": 4, "col": 1, "color": "red" }],
  "buttons": [{ "row": 1, "col": 1, "color": "red" }],
  "ball": { "row": 0, "col": 0 },
  "hole": { "row": 5, "col": 5 },
  "par": 14
}
```

빈 유리·색·버튼 배열은 파일에서 생략해도 된다. 로더는 없으면 빈 격자로 본다.

## 3. 특수 규칙 (변수 타일)

### 3.1 유리벽 (Glass Wall) — Phase B 우선

| 항목 | 내용 |
|------|------|
| **동작** | 공이 그 엣지를 **처음 통과 시도** → 금 간 상태, **통과 불가** |
| **2번째** | 같은 엣지로 다시 밀리면 → **파괴**, 이후 일반 통로 |
| **카운트** | “기울임 1회”가 아니라 **그 벽에 공이 닿은 슬라이드 시도 횟수**로 할지, “플레이어 턴 수”로 할지 → **슬라이드 시도** 권장 (직관적) |
| **연출** | 크랙 텍스처 → 파편 VFX + 짧은 SFX |
| **난이도** | 같은 optimal 경로라도 **실질 이동 수 +1~2** 체감 |

**시뮬레이션 확장:** `GameSimulation`에 `glassWalls[edge] → hits (0|1|broken)` 상태 추가.

### 3.2 워프 (Warp) — Phase C

- 칸 A ↔ 칸 B 쌍; 공 진입 시 순간이동 후 **같은 방향으로 슬라이드 계속** (또는 정지 — 밸런스 결정 필요)
- 5×5 이후, optimal 검증 필수

### 3.3 기타 후보 (메모)

- **일회용 바닥** (한 번 지나면 함몰)
- **방향 화살표 바닥** (강제 방향)
- **이동 제한 횟수** 스테이지 (최대 N번 기울임)

## 4. 메타 진행 · 리텐션 · 리워드

### 4.1 루프 (상위권 캐주얼 표준)

```
스테이지 플레이 → 클리어 → 보상 획득 → 메타에 사용 → 다음 스테이지 / 일일 / PvP
```

### 4.2 클리어 보상 (1판 직후)

| 보상 | 용도 |
|------|------|
| **코인** (소프트) | 스킨·힌트·Undo 구매 |
| **별** (1~3) | 월드 언락·게이트 |
| **경험치** | 계정 레벨 → 기능 언락 |
| **가챠 티켓** (저빈도) | 스킨 뽑기 |

- **광고 (선택):** 보상 2배, 유리벽 스테이지 실패 후 **1회 Undo**  
- Block Blast 리뷰 교훈: **강제 긴 전면광고** 지양 → 클리어·메뉴 전환에만

### 4.3 수집 · 커스터마이즈 (아바타/테마)

| 카테고리 | 예시 | 희귀도 |
|----------|------|--------|
| **공 스킨** | 금속, 유리, 이모지, 시즌 | ★~★★★ |
| **테이블 배경** | 나무, 대리석, 우주, 시즌 | ★~★★★ |
| **벽 스킨** | 나무 / 유리 / 브릭 / 네온 | ★~★★ |
| **구멍 이펙트** | 링 색, 파티클 | ★★ |
| **트레이 장식** | 테이블 위 피규어·스티커 (배경 인형) | ★★~★★★ |

- **장착 슬롯:** 공 1 + 테이블 1 + 벽 1 + FX 1 + 장식 1  
- **획득 경로:** 스테이지 첫 클리어, 별 모음, 일일 미션, 시즌 패스, (PvP) 랭크 보상

### 4.4 일일 · 주간 (재방문)

- **일일 퍼즐** 1판 (고정 시드) — 전 세계 동일, 리더보드 최소 이동  
- **주간 챌린지** 5×5 하드 1개  
- **연속 출석** 7일 → 스킨 조각

### 4.5 유저 유입 (성장) — 개발과 병행

| 채널 | 액션 |
|------|------|
| ASO | “기울이기”, “미로”, “두뇌”, “3D 퍼즐” 키워드, 스크린샷 6장 (3D 테이블) |
| 소프트 런치 | 한국 → 필리핀/캐나다 등 |

## 5. 매치 모드 (Phase D) — 1:1 PvP

### 5.1 개요

- 보드: **4×4 또는 5×5**
- **턴제** — 블루 vs 레드
- **블루 공 → 블루 구멍**, **레드 공 → 레드 구멍** (자기 색만 클리어)
- **먼저 자기 구멍에 넣는 쪽 승리**

### 5.2 턴 구조 (안)

| 페이즈 | 행동 |
|--------|------|
| 내 턴 | (1) **기울이기** 1회 **또는** (2) **벽 설치** 1개 (엣지, 제한 규칙) |
| 상대 턴 | 동일 |
| 제한 | 턴 시간 15~30초, 연장 3회/판 |

- **벽 설치:** 남은 “벽 카운트” 소모, 상대 경로 방해 (밸런스 핵심)
- **동시 슬라이드**는 하지 않음 (턴제로 명확히)

### 5.3 랭크 · 매칭

- **ELO 또는 티어** (브론즈 ~ 챌린저)
- 시즌 4~6주, 시즌 스킨
- **친선 / 랭크** 분리
- 연승 보너스 코인 (과도한 스노우볼 방지 캡)

### 5.4 기술 메모 (나중에)

- Photon Fusion / Unity Netcode / PlayFab Turn-based 등 비교
- **결정론 시뮬** 필수: `GameSimulation`을 서버·클라 공유
- 치트 방지: 행동만 서버 검증

## 7. Block Blast vs In the Hole (혼동 방지)

| | Block Blast | In the Hole |
|---|-------------|-------------|
| 조작 | 블록 드래그 배치 | 테이블 기울임 |
| 목표 | 줄 완성 제거 | 공 → 구멍 |
| 참고점 | **UX·수익·연출·운영** | **우리 장르 유지** |
